# Safe Git Workflow

## ルール

- **commit / push / force-push は、ユーザーが明示的に指示するまで絶対に実行しない**
- コード変更が完了したら、まず変更内容のサマリを提示してユーザーに確認を求める
- ユーザーが「コミットして」「pushして」等と明言した場合のみ実行する
- 「変更を適用して」「修正して」等の指示はファイル編集の許可であり、commit/push の許可ではない
- 「pushして」は commit + push の許可として扱う（未commitの変更がある場合、commitも含む意図と解釈する）

## 確認フロー

ユーザーから commit / push の許可を得た場合でも、以下の確認フローは**必ず実行する**（省略不可）。

1. 変更対象ファイルと変更内容のサマリを提示
2. コミットメッセージ案を提示
3. push 先のリモート・ブランチを明示（push を含む場合）
4. ユーザーの承認を待つ
5. 承認後にのみ `git add` + `git commit`（+ `git push`）を実行
